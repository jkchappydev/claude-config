# 원격 서버 로그/헬스체크 가이드

## 0. 절대 원칙 (읽기 전용)

- `docker restart`, `docker stop`, `docker rm`, `kill`, 서비스 재기동 등 **상태를 바꾸는 명령은 절대 실행하지 않는다.**
- 이 스킬은 오직 조회만 한다: `docker ps`, `curl`(GET), `tail`/`grep`(로그 읽기).
- 이상이 발견되면 사용자에게 보고만 하고, 재기동 여부는 사용자가 직접 판단해서 IntelliJ 등에서 수행한다 (CLAUDE.md 애플리케이션 실행/종료 정책 참고).

## 1. 대상 서버 파악

- 서버별 SSH 접속 정보·헬스체크 URL·로그 경로는 `~/.claude/references/` 아래 프로젝트별 참고 파일(예: `lifebooks-servers.md`)의 "헬스체크 정보" 섹션에 정리되어 있다.
- 사용자가 어떤 서버를 말하는지 애매하면, 참고 파일에 등록된 서버 별칭 목록을 보여주고 하나를 고르게 한다.
- 참고 파일에 헬스체크 정보가 없는 서버라면, 먼저 그 서버의 컨테이너명/헬스체크 URL/로그 경로를 물어보고 참고 파일에 추가해 둔다.

## 2. 점검 순서

1. **프로세스 생존 확인**: `ssh <서버> "docker ps --filter name=<컨테이너명>"`
   - 컨테이너 자체가 없으면 즉시 "컨테이너 다운" 으로 보고하고 이후 단계는 생략한다.
   - actuator 대상이 아닌 배치성 프로세스는 `ps -ef | grep <jar명>`으로 대체한다.
2. **헬스체크 호출**: actuator URL이 등록되어 있으면 `curl -s -o /dev/null -w "%{http_code}" <URL>`로 HTTP 상태 코드만 확인한다.
   - 200이 아니면 실제 응답 본문(`curl -s <URL>`)까지 가져와 원인을 같이 보고한다.
3. **최근 로그 확인**: 로그 디렉터리가 등록되어 있으면
   - `ssh <서버> "ls -t <로그디렉터리> | head -1"`로 실제 최신 로그 파일명을 먼저 확인한다 (설정에 적힌 파일명과 다를 수 있음, 파일명을 하드코딩하지 않는다).
   - `ssh <서버> "tail -n 200 <최신로그파일> | grep -iE 'error|exception'"`로 최근 에러만 추출한다.

## 3. 결과 보고 형식

```
## <서버 별칭> 상태

- 프로세스: OK / 다운
- 헬스체크: UP (200) / DOWN (<코드>, <응답요약>) / 대상 아님
- 최근 에러 로그: 없음 / <건수>건 발견 (파일: <경로>)
  - [있다면 대표적인 에러 1~2줄 인용]
```

- 여러 서버를 한 번에 물어보면 서버별로 위 형식을 반복한다.
- 문제가 없어도 "정상"이라고만 하지 말고 위 3개 항목을 모두 채워서 보고한다 — 무엇을 확인했는지가 드러나야 신뢰할 수 있다.
