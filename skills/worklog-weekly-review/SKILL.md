# 주간 워크로그 회고

## 동작 방식

- **기본**: 현재 프로젝트의 `docs/worklog/YYYY-MM-DD-*.md`(이번 주 월~일, 모든 작성자 파일)만 정리한다.
- **통합 모드**: 사용자가 "통합 회고", "여러 프로젝트"를 요청했거나, 실행 위치가 전역 `~/.claude`면 통합 모드로 동작한다. 전역에서는 항상 통합 모드다.

각 일일 워크로그 파일 상단의 `작성자: {이름}`을 읽어, 그 파일에서 나온 작업 항목에 작성자를 표시한다 (아래 "작성자 표시" 참고).

### 레거시 파일 호환

사용자별 파일명 규칙 도입 이전에 쓰이던 `docs/worklog/YYYY-MM-DD.md`(작성자 접미사 없음)도 함께 대상으로 한다.

- 신규 형식(`YYYY-MM-DD-*.md`)과 레거시 형식(`YYYY-MM-DD.md`)을 모두 읽는다.
- 같은 날짜에 신규 형식 파일이 하나라도 있으면, 그 날짜의 레거시 파일은 무시한다(중복 방지).
- 레거시 파일에는 작성자 정보가 없으므로, 그 파일에서 나온 항목에는 `[이름]` 태그를 붙이지 않는다.

## 통합 모드

- 대상: `~/.claude/references/worklog-projects.local.md`에 등록된 프로젝트.
- 등록된 프로젝트 경로가 존재하지 않거나 `docs/worklog/`가 없으면 해당 프로젝트는 건너뛴다.
- `worklog-projects.local.md`가 없으면, 템플릿(`worklog-projects.md`)을 복사해서 만들라고 안내하고 종료한다.
- `worklog-projects.md`는 git에 커밋되는 템플릿일 뿐이므로 대상 목록으로 읽지 않는다.

## 저장

- 개별 프로젝트: `docs/worklog/weekly/YYYY-Www.md`
- 전역 `~/.claude`: `~/.claude/worklog-weekly/YYYY-Www.md`

대상 기간에 워크로그가 하나도 없으면 파일을 만들지 않고 종료한다.

## 작성 형식

```markdown
# YYYY-Www 주간보고 (YYYY-MM-DD ~ YYYY-MM-DD)

## 완료된 작업
- [이름] ...

## 진행 중 / 이슈
- [이름] [이슈명]: 현재 상황 → 다음 액션

## 다음 주 예정
- ...
```

통합 주간보고는 각 항목 안에서 프로젝트별로 구분한다.

## 작성자 표시

- 각 일일 워크로그 파일 상단 `작성자: {이름}`을 그 파일에서 나온 작업의 작성자로 쓴다. 이름을 추측하지 않는다.
- 같은 작업에 여러 사람이 참여한 것으로 판단되면 `[이름1, 이름2]`처럼 표시한다.

## 작성 원칙

이 보고도 `daily-worklog`와 마찬가지로 "무엇을 했는지 빠르게 파악"하는 용도이고, 일일보고보다 **한 단계 더 결과 중심**으로 쓴다. 날짜별·파일별 항목을 그대로 나열하지 않는다.

**무엇을 합칠지** — "주간보고니까 더 짧게"가 아니라 **"같은 목적의 작업인가"**로 판단한다.

- 여러 날짜에 걸쳐 이어진 동일 목적의 작업 → 통합
- 같은 기능을 구현하면서 생긴 후속 수정 → 통합 가능
- 서로 독립적으로 발생한 버그나 기능 → 별도 유지. 일일보고에서 별도 항목이었다면 항목 수를 줄이려고 다시 합치지 않는다.

**어떻게 쓸지**

- 완료된 작업은 무엇을 했고 결과가 어땠는지 한 줄 위주로 드러나게 쓴다. 구현 세부사항은 꼭 필요할 때만 남긴다.
- merge·branch·commit 같은 Git 작업 과정은 그 자체가 업무 결과가 아니면 문구에서 뺀다.
  - `도서 삭제 기능 구현 및 release 병합 — …` → `도서 삭제 기능 구현 — 연관 콘텐츠가 있는 도서는 삭제를 차단하고 종속 데이터 처리까지 반영`
- 진행 중인 이슈는 현재 상황과 다음 액션을 함께 쓴다.

**시행착오가 되살아나지 않게** — 여러 일일보고를 통합하면서 과거 워크로그의 시행착오·추정·경위가 최종 문구에 다시 섞이지 않게 한다. 남길 것은 현재 상태와 앞으로 필요한 액션이다.

- `카테고리 컬럼명이 DB 쪽에서 반복 변경되고 있음 → …`(경위·추정이 되살아난 표현) → `도서 카테고리 관련 작업: DB 컬럼 변경 이력이 있어 수정 전 실제 컬럼명 재확인 필요`(중립적 현재 상태)

기존 일별 워크로그는 수정하지 않는다.
