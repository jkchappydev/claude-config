# 주간 업무 보고

## 대상

`~/.claude/daily-report/` 아래의 프로젝트별 폴더를 전부 훑어서 이번 주 월~금 업무 보고를 모은다. 프로젝트 디렉터리를 직접 찾아가지 않는다.

```text
~/.claude/daily-report/
├── project-a/
│   ├── 2026-08-18-user1.md
│   └── 2026-08-19-user1.md
└── project-b/
    └── 2026-08-20-user1.md
```

- 신규: `YYYY-MM-DD-*.md`
- 레거시: `YYYY-MM-DD.md` (작성자 접미사 없는 옛 형식)

같은 날짜에 신규 파일이 하나라도 있으면 그 날짜의 레거시 파일은 읽지 않는다.

신규 파일은 상단의 `작성자: {이름}`을 읽어 작업 앞에 `[이름]`을 붙인다. 레거시 파일은 작성자 정보가 없으므로 이름을 붙이지 않는다.

`~/.claude/daily-report/`가 아직 없거나 비어 있으면, 이번 주 대상 업무 보고가 없다는 뜻이므로 파일을 만들지 않는다.

## 저장

`~/.claude/weekly-report/YYYY-Www.md` 하나만 만든다. 프로젝트별 주간 업무 보고는 만들지 않는다.

이번 주 업무 보고가 없으면 파일을 만들지 않는다.

## 완료 날짜

각 완료 작업 앞에 `[YYYY-MM-DD]`로 완료 날짜를 붙인다.

- 날짜는 그 작업이 적힌 일일 업무 보고의 날짜를 그대로 쓴다. Git commit 시각 등으로 다시 추측하지 않는다.
- 여러 날짜의 작업을 하나로 통합했으면, 통합에 포함된 날짜 중 가장 마지막 날짜를 완료일로 쓴다.
- 날짜를 맞추려고 서로 다른 독립된 작업을 합치지 않는다.

## 형식

```markdown
# YYYY-Www 주간 업무 보고 (YYYY-MM-DD ~ YYYY-MM-DD)

## 완료된 작업

### 프로젝트명
- [YYYY-MM-DD] [이름] 작업 내용
- ...
```

주간보고에는 완료된 작업만 넣는다.

- `진행 중 / 이슈`는 가져오지 않는다.
- `다음 주 예정` 같은 미래 계획은 만들지 않는다.
- 미완료 작업을 완료된 것처럼 바꾸지 않는다.
- Git 기록이나 문맥만 보고 완료 여부를 추측하지 않는다.
- 완료된 작업이 없는 프로젝트는 표시하지 않는다.

## 정리 기준

날짜별 내용을 그대로 붙이지 않는다.

- 여러 날 이어진 같은 작업은 하나로 합친다.
- 같은 기능의 후속 수정은 함께 묶을 수 있다.
- 목적이 다른 버그나 기능은 따로 둔다.
- 항목 수를 줄이려고 서로 다른 업무를 합치지 않는다.
- 같은 작업에 여러 사람이 참여했으면 `[이름1, 이름2]`처럼 표시한다.
- 이름은 일일보고에 적힌 값을 그대로 쓰고 추측하지 않는다.

일일보고보다 결과 중심으로 정리한다.

- 무엇을 했고 무엇이 달라졌는지가 보이면 충분하다.
- 구현 세부사항은 필요한 만큼만 남긴다.
- merge, branch, commit 같은 Git 과정은 업무 결과가 아니면 뺀다.
- 여러 일일보고를 합치면서 예전 시행착오나 추정을 다시 넣지 않는다.
- 최종적으로 확정된 결과와 작업 범위만 남긴다.
- 문체는 `daily-report`의 `문체` 기준을 그대로 따른다.

예:

```text
도서 삭제 기능 구현 및 release 병합
→ 도서 삭제 기능 구현, 연관 콘텐츠가 있는 경우 삭제되지 않도록 처리
```

기존 일일 업무 보고는 수정하지 않는다.
