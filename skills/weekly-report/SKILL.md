# 주간 업무 보고

## 대상

`~/.claude/daily-report/` 아래에서 이번 주 월~금에 해당하는 날짜별 일일 업무 보고 파일을 읽는다.

```text
~/.claude/daily-report/
├── 2026-08-18-user1.md
├── 2026-08-19-user1.md
└── 2026-08-20-user1.md
```

각 파일 안의 `## {프로젝트명}` 섹션과 그 아래 `### 완료된 작업`을 기준으로 프로젝트별 업무를 취합한다.

예:

```markdown
# 2026-08-20 일일 업무 보고

작성자: 홍길동

## project-a

### 완료된 작업
- ...

## project-b

### 완료된 작업
- ...
```

- 파일명 형식은 `YYYY-MM-DD-{사용자ID}.md`를 기본으로 한다.
- 같은 날짜에 여러 사용자 파일이 있으면 각각 읽고, 파일 상단의 `작성자: {이름}`을 사용한다.
- 프로젝트명은 각 파일 내부의 `## {프로젝트명}` heading을 그대로 사용하며 임의로 바꾸거나 추측하지 않는다.
- `~/.claude/daily-report/`가 아직 없거나 비어 있으면, 이번 주 대상 업무 보고가 없다는 뜻이므로 파일을 만들지 않는다.

## 저장

`~/.claude/weekly-report/YYYY-Www.md` 하나만 만든다. 프로젝트별 주간 업무 보고는 만들지 않는다.

이번 주 업무 보고가 없으면 파일을 만들지 않는다.

## 기간 표기

각 완료 작업 앞에는 그 업무가 일일 업무 보고에 기록된 기간을 표시한다.

- 하루에만 기록된 작업: `[MM-DD]`
- 여러 날짜에 걸쳐 같은 업무가 기록된 경우: `[MM-DD ~ MM-DD]`
- 날짜는 일일 업무 보고 파일 날짜를 그대로 쓴다. Git commit 시각 등으로 다시 추측하지 않는다.
- 여러 날짜의 같은 작업을 통합했으면, **그 업무가 일일 업무 보고에 기록된 최초 날짜 ~ 마지막 날짜**를 표시한다.
- 이 범위는 매일 연속으로 작업했다는 뜻이 아니다. 중간 날짜에 기록이 없어도 동일 업무의 최초 기록일과 마지막 기록일 기준으로 표시한다.
- 날짜를 맞추기 위해 서로 다른 독립 업무를 합치지 않는다.
- 프로젝트 내부에서는 시작 기록일 기준 오름차순으로 정렬한다.
- 연도는 주간보고 제목에 있으므로 항목 날짜에서는 생략한다.

예:

```text
[08-21] 로그인 리다이렉트 오류 수정
[08-19 ~ 08-21] 도서 등록·수정 화면 구현
```

## 형식

```markdown
# YYYY-Www 주간 업무 보고 (YYYY-MM-DD ~ YYYY-MM-DD)

## 완료된 작업

### 프로젝트명
- [MM-DD] [이름] 작업 내용
- [MM-DD ~ MM-DD] [이름] 작업 내용
```

주간보고에는 완료된 작업만 넣는다.

- 일일보고의 `### 진행 중 / 이슈`는 가져오지 않는다.
- `남은 작업` 섹션을 만들지 않는다.
- `다음 주 예정` 같은 미래 계획은 만들지 않는다.
- 미완료 작업을 완료된 것처럼 바꾸지 않는다.
- Git 기록이나 문맥만 보고 완료 여부를 추측하지 않는다.
- 완료된 작업이 없는 프로젝트는 표시하지 않는다.

## 정리 기준

날짜별 내용을 그대로 붙이지 않는다.

- 여러 날짜에 기록된 같은 작업은 하나로 합친다.
- 같은 기능의 후속 수정은 함께 묶을 수 있다.
- 목적이 다른 버그나 기능은 따로 둔다.
- 항목 수를 줄이려고 서로 다른 업무를 합치지 않는다.
- 같은 작업에 여러 사람이 참여했으면 `[이름1, 이름2]`처럼 표시한다.
- 이름은 각 일일보고 상단에 적힌 `작성자:` 값을 그대로 쓰고 추측하지 않는다.

일일보고보다 결과 중심으로 정리한다.

- 무엇을 했고 무엇이 달라졌는지가 보이면 충분하다.
- 구현 세부사항은 필요한 만큼만 남긴다.
- merge, branch, commit 같은 Git 과정은 업무 결과가 아니면 뺀다.
- 여러 일일보고를 합치면서 예전 시행착오나 추정을 다시 넣지 않는다.
- 최종적으로 확정된 결과와 작업 범위만 남긴다.
- 문체는 `daily-report`의 `문체` 기준을 그대로 따른다.

예:

```text
도서 삭제 기능 구현 및 release 병합
→ 도서 삭제 기능 구현, 연관 콘텐츠가 있는 경우 삭제되지 않도록 처리
```

기존 일일 업무 보고는 수정하지 않는다.
