# 업무 보고 SKILL 사용설명서

Claude를 이용해 **하루 업무를 날짜별 파일 하나에 기록**하고, 파일 내부에서 프로젝트별로 구분한 뒤 여러 날짜의 일일보고를 모아 **주간 업무 보고**를 만드는 SKILL입니다.

업무 보고 파일은 프로젝트 Git 저장소에 넣지 않습니다.

```text
프로젝트 Git 저장소
→ 소스코드만 관리

~/.claude/daily-report/YYYY-MM-DD-{사용자ID}.md
→ 하루 일일 업무 보고 하나
→ 파일 내부에서 프로젝트별로 구분

~/.claude/weekly-report/YYYY-Www.md
→ 개인 주간 업무 보고
```

---

## 1. ZIP 파일 배치

전달받은 ZIP 파일의 압축을 해제합니다.

구성:

```text
README.md
CLAUDE.md

skills/
├── daily-report/
│   └── SKILL.md
└── weekly-report/
    └── SKILL.md
```

`skills` 폴더를 Claude 전역 설정 폴더인 `~/.claude` 아래에 배치합니다.

Windows 기준:

```text
C:\Users\{사용자명}\.claude
```

최종적으로 다음 파일이 있으면 됩니다.

```text
~/.claude/
└── skills/
    ├── daily-report/
    │   └── SKILL.md
    └── weekly-report/
        └── SKILL.md
```

ZIP의 `CLAUDE.md`는 **참고용**입니다. 기존에 사용 중인 `~/.claude/CLAUDE.md`가 있다면 덮어쓰지 말고 아래 필수 규칙만 복사해서 추가합니다.

---

## 2. CLAUDE.md 필수 설정

### 2-1. 커밋 규칙에 추가

기존 `## 커밋 규칙`에 아래 내용을 추가합니다.

```markdown
- **커밋할 때마다 오늘 날짜 업무 보고를 함께 업데이트할 것**
  - 순서: `daily-report` 스킬로 오늘 업무 보고를 먼저 작성/갱신한 다음 `git commit`을 실행한다
  - SKILL 파일이 있다고 자동 실행되는 게 아니므로, 커밋 요청을 받으면 `daily-report`부터 실행한다
```

### 2-2. 업무 보고 관리 규칙 추가

```markdown
## 업무 보고 관리

### 일일 업무 보고
- 일일 업무 보고는 프로젝트 Git 저장소에 저장하지 않는다
- 날짜별 사용자 파일 하나에 여러 프로젝트의 업무를 함께 기록한다
  - `~/.claude/daily-report/YYYY-MM-DD-{사용자ID}.md`
- 현재 Git repository의 루트 디렉터리명을 프로젝트명으로 사용하고, 파일 내부 `## {프로젝트명}` 섹션만 추가하거나 갱신한다
- 다른 프로젝트 섹션은 수정하거나 삭제하지 않는다
- 작성자 식별, 작업 단위 정리, 정보 출처 우선순위 등 상세 규칙은 `daily-report` 스킬을 따른다
- 지난 날짜 파일은 원칙적으로 수정하지 않는다
- 사용자가 특정 지난 날짜의 업무 보고 작성을 명시적으로 요청한 경우에는 `daily-report` 규칙에 따라 해당 프로젝트 섹션을 복원할 수 있다

### 주간 업무 보고
- `~/.claude/daily-report/`의 날짜별 일일 업무 보고를 읽고 파일 내부 프로젝트 섹션을 취합한다
- 전역에 주간 업무 보고 하나만 저장한다
  - `~/.claude/weekly-report/YYYY-Www.md`
- 상세 규칙은 `weekly-report` 스킬을 따른다
```

기존 개인 `CLAUDE.md`의 나머지 규칙은 그대로 유지합니다.

---

## 3. 사용자 이름 최초 설정

각 사용자 PC에서 최초 1회 업무 보고에 표시할 이름을 설정합니다.

예:

```bash
git config --global report.name "홍길동"
```

확인:

```bash
git config --global --get report.name
```

`report.name`은 업무 보고에 표시할 이름입니다.

기존 Git 커밋 작성자 설정인 `git config user.name`과는 별개이므로 Git author에는 영향을 주지 않습니다.

---

## 4. 사용자ID 확인

사용자ID는 별도로 설정하지 않습니다.

현재 프로젝트의 Git 이메일에서 `@` 앞부분을 사용합니다.

```bash
git config user.email
```

예:

```text
honggildong@eco.co.kr
→ 사용자ID: honggildong
```

일일 업무 보고 파일명:

```text
YYYY-MM-DD-{사용자ID}.md
```

별도의 프로젝트 경로 등록이나 `report-projects` 설정은 필요하지 않습니다.

# 일일 업무 보고

## 5. 저장 위치

```text
~/.claude/daily-report/YYYY-MM-DD-{사용자ID}.md
```

예:

```text
~/.claude/daily-report/2026-08-25-honggildong.md
```

하루에 여러 프로젝트를 작업해도 파일은 하나만 사용합니다. 프로젝트는 파일 내부의 `## 프로젝트명`으로 구분합니다.

따라서 업무 보고 때문에 프로젝트의 `.gitignore`를 수정하거나 전역 Git ignore를 설정할 필요가 없습니다.

---

## 6. 여러 프로젝트를 작업한 경우

오전에 `project-a`에서 업무를 작성하고 오후에 `project-b`에서 다시 `daily-report`를 실행해도 같은 날짜 파일을 사용합니다.

```markdown
# 2026-08-20 일일 업무 보고

작성자: 홍길동

## project-a

### 완료된 작업
- 도서 목록 조회 성능 개선
- 사용하지 않는 도서 카테고리 기능 제거

### 진행 중 / 이슈
- ...

## project-b

### 완료된 작업
- 추천도서 등록 API 500 에러 수정

### 진행 중 / 이슈
- ...
```

`project-b`를 추가하거나 갱신할 때 기존 `project-a` 내용은 그대로 유지합니다.

---

## 7. 사용 방법

### Claude로 커밋하는 경우

평소처럼 요청합니다.

```text
커밋해줘
```

`CLAUDE.md` 규칙이 적용되어 있으면:

```text
커밋 요청
→ daily-report 실행
→ 오늘 일일 업무 보고의 현재 프로젝트 섹션 작성/갱신
→ git commit
```

순서로 동작합니다.

> SourceTree 등 Claude 밖에서 직접 커밋하면 그 순간 `daily-report`가 자동 실행되지는 않습니다.

### 일일 업무 보고만 작성

```text
오늘 일일 업무 보고 작성해줘
```

처럼 직접 요청할 수도 있습니다.

## 8. 일일보고 확인 기준

현재 프로젝트 섹션을 기준으로 다음 순서로 확인합니다.

1. 오늘 기존 업무 보고의 현재 프로젝트 섹션
2. 오늘 날짜의 현재 사용자 Git commit
3. staged / unstaged 변경

다른 프로젝트 섹션은 현재 프로젝트 작업을 확인하는 과정에서 수정하지 않습니다.

기존 보고에 적힌 내용은 뒤의 Git 자료만 보고 지우지 않습니다.

운영 DB 작업, 서버 설정, 장애 대응, 테스트, 분석처럼 Git에 남지 않는 작업도 기존 보고에 적혀 있으면 유지합니다.

### staged / unstaged 변경

staged / unstaged는 **무슨 작업을 했는지 파악하는 보조 자료**입니다.

변경사항이 있다는 이유만으로 완료된 작업으로 처리하지 않습니다.

완료 여부가 불분명하면 임의로 완료 처리하지 않고 필요한 경우 `진행 중 / 이슈`로 정리합니다.

---

## 9. 업무 단위 정리

커밋 하나를 업무 하나로 보지 않습니다.

- 여러 커밋이 같은 목적이면 하나의 업무로 통합
- 하나의 커밋에 독립적인 목적의 업무가 여러 개면 분리 가능
- 커밋 메시지를 그대로 복사하지 않고 필요하면 diff를 확인

분리 기준은 **코드가 다르게 바뀌었는지**가 아니라 **업무 목적이 독립적으로 다른지**입니다.

예:

```text
분리 O
- 도서 목록 조회 500 에러 수정
- 사용하지 않는 도서 카테고리 기능 제거
```

버그 수정과 기능 제거는 서로 독립적인 업무 목적이므로 분리할 수 있습니다.

반대로:

```text
분리 X
- 추천도서 등록 API 500 에러 수정
- 수정 과정에서 같이 처리한 사용하지 않는 컬럼 주석처리
```

단순 컬럼 정리, 주석처리, 의존성 정리, 내부 코드 정리 등은 상위 업무의 구현 세부사항이면 별도 업무로 만들지 않습니다.

---

## 10. 지난 날짜 일일 업무 보고

기본적으로 지난 날짜의 보고는 임의로 수정하지 않습니다.

다만 사용자가 특정 날짜를 명시해서 요청하면 해당 날짜 파일의 **현재 프로젝트 섹션만** Git 기록을 기준으로 복원할 수 있습니다.

예:

```text
2026-08-20 일일 업무 보고 작성해줘
```

이 경우:

- 현재 프로젝트의 기존 섹션이 있으면 내용 보존
- 같은 날짜 파일의 다른 프로젝트 섹션은 그대로 보존
- 해당 날짜 Git commit 기준으로 현재 프로젝트 작업만 복원
- Git이나 기존 보고에 남지 않은 작업은 추측하지 않음
- 현재 staged / unstaged 변경을 과거 작업으로 넣지 않음

따라서 SourceTree 등에서 직접 커밋해 당시 일일보고가 만들어지지 않았더라도, 나중에 Git 기록이 남아 있는 범위에서는 복원할 수 있습니다.

# 주간 업무 보고

## 12. 대상

`weekly-report`는 아래 날짜별 일일보고를 직접 읽습니다.

```text
~/.claude/daily-report/
├── 2026-08-18-honggildong.md
├── 2026-08-19-honggildong.md
├── 2026-08-20-honggildong.md
└── 2026-08-21-honggildong.md
```

각 파일 안의 `## 프로젝트명` 섹션을 기준으로 프로젝트별 완료 업무를 취합합니다.

별도로 프로젝트 경로를 등록할 필요가 없습니다.

대상 기간은 **월요일 ~ 금요일**입니다.

---

## 13. 사용 방법

Claude에게 다음과 같이 요청합니다.

```text
이번 주 주간 업무 보고 작성해줘
```

또는 특정 주를 지정할 수도 있습니다.

```text
지난주 주간 업무 보고 작성해줘
```

---

## 14. 저장 위치

```text
~/.claude/weekly-report/YYYY-Www.md
```

각 프로젝트 내부에는 주간 업무 보고를 만들지 않습니다.

---

## 15. 주간 업무 보고 형식

```markdown
# YYYY-Www 주간 업무 보고 (YYYY-MM-DD ~ YYYY-MM-DD)

## 완료된 작업

### project-a
- [08-20] [{이름}] 작업 내용
- [08-20 ~ 08-21] [{이름}] 작업 내용

### project-b
- [08-21] [{이름}] 작업 내용
```

주간 업무 보고에는 **완료된 작업만** 작성합니다.

다음 내용은 포함하지 않습니다.

```text
진행 중 / 이슈
남은 작업
다음 주 예정
```

---

## 16. 주간보고 날짜 표기

하루에만 기록된 작업:

```text
[08-21] [홍길동] 작업 내용
```

여러 날짜에 걸쳐 같은 업무가 기록된 경우:

```text
[08-20 ~ 08-21] [홍길동] 작업 내용
```

`[08-20 ~ 08-21]`은 **08-20부터 08-21까지 매일 연속으로 작업했다는 뜻이 아닙니다.**

정확한 의미는:

> 동일 업무가 일일 업무 보고에 기록된 최초 날짜 ~ 마지막 날짜

입니다.

예를 들어 08-19에 작업 기록이 있고, 08-20에는 없고, 08-21에 같은 업무의 후속 작업이 기록된 경우에도:

```text
[08-19 ~ 08-21]
```

로 표시할 수 있습니다.

프로젝트 내부에서는 시작 기록일 기준으로 정렬합니다.

---

## 17. 주간보고 통합 기준

날짜별 내용을 그대로 붙이지 않습니다.

- 여러 날짜에 기록된 같은 업무는 하나로 통합
- 같은 기능의 후속 수정은 함께 묶을 수 있음
- 목적이 다른 업무는 별도로 유지
- 항목 수를 줄이기 위해 서로 다른 업무를 억지로 합치지 않음
- 완료 여부를 Git 기록만 보고 새로 추측하지 않음
- merge, branch, commit 등 Git 과정은 업무 결과가 아니면 제외
- 시행착오보다 최종 결과와 작업 범위를 중심으로 작성

# 문체

AI가 정리한 보고서처럼 과하게 다듬기보다 실제 개발자가 사내 업무보고에 작성하는 수준으로 정리합니다.

```text
X  운영 DB에서 구 테이블을 참조하던 잔존 FK 6개 정리 — 등록 실패 해소
O  운영 DB에 남아있던 구 테이블 FK 6개 정리, 등록 오류 수정
```

```text
X  도서 삭제 기능 구현 — 연관 콘텐츠가 있는 도서는 삭제를 차단하고 종속 데이터 처리까지 반영
O  도서 삭제 기능 구현, 연관 콘텐츠가 있는 경우 삭제되지 않도록 처리
```

# 주요 파일 구조

```text
~/.claude/
├── skills/
│   ├── daily-report/
│   │   └── SKILL.md
│   └── weekly-report/
│       └── SKILL.md
├── daily-report/
│   ├── YYYY-MM-DD-{사용자ID}.md
│   └── ...
└── weekly-report/
    └── YYYY-Www.md
```

`daily-report/`, `weekly-report/` 아래의 실제 보고 데이터는 개인 로컬 데이터이며 팀 배포 ZIP에는 포함하지 않습니다.
